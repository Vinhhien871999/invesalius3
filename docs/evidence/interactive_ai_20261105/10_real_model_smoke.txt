## Defect found by the real runtime (fixed before these runs)
The first real PROBE hung: worker.py's stdin reader thread was blocked in a synchronous read on the stdin pipe, and the
lazy `import numpy` loaded numpy's OpenBLAS (with its own msvcp140 CRT), whose initialisation calls GetFileType on the
standard handles - which blocks on Windows while a read is pending on that pipe. The fake worker never showed it because
it imports numpy before the reader starts. Fix: on Windows pipes the reader polls PeekNamedPipe and reads only available
bytes. Regression test: test_lazy_dll_import_after_the_reader_started_does_not_hang (verified to time out with the old
worker.py, pass with the new one).
